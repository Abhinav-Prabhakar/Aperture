Data Explorer

A filter rail, a measurement table, and an inspector that keeps the selected sample in view. One screen for the question researchers ask most: what is in this run, and what does one row mean?

Open full screenSynthetic run, real interactions.

What is inside

  • Filter rail. Text search, QC status, and treatment. Counts make the effect of a filter visible before you apply it.
  • Table. One unit per column, tabular numerals, explicit — for missing concentrations, and stable sorting that puts missing last.
  • Inspector. The active row’s measurement, 12-hour series, note, and chain of custody. Selection for export is separate from the row you are reading.
  • Export. A real CSV of the current view, or of the selected rows when there is a selection. File names and units are stable.
  • Print. A print stylesheet drops the filter rail and actions, keeping the run header, summary, and table.

Every state

Each state has its own page. Nothing is a blank screen, and none of them pretends an error is an empty result.

  • Ready
  • Loading
  • Empty
  • Error
  • Permission denied
  • Offline

Install

The workbench installs its instruments and elements from the registry. No private runtime, no hidden provider.

Rules

  • Compose, do not fork. If the workbench needs a new primitive, add it to the registry first so every workbench gets it.
  • Missing is a measurement state, not a layout accident. A censored concentration is — with a reason in the note, never zero.
  • The row count, filter counts, and export must all describe the same set. If the table says 24 rows, the CSV does not get 22.
  • A permission error is not an empty dataset. Say what is restricted and who can grant access.
  • Keep the export client-side unless the dataset requires otherwise. A view you can see is a view you can save.
