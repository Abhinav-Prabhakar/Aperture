Lab Dashboard

The morning question for a lab: what is running, what is broken, and what needs a person? Instruments, samples, alerts, and the day’s schedule on one screen, with every number traceable to a timestamp.

Open full screenSynthetic lab, real interactions.

What is inside

  • Instrument health. A card per instrument with state, current activity, run progress, 7-day utilization, and the next calibration. Details open without leaving the page.
  • Alerts that stay visible. Acknowledging an alert removes it from the open count and keeps the record on screen. Nothing disappears because someone clicked once.
  • Samples in flight. Stage, instrument, operator, and a real ETA. Queued and blocked samples are distinct from running ones.
  • Today’s schedule. Completed, running, and waiting runs share one timeline, so the day reads in order.
  • Recent activity. A filterable log with levels, sources, and timestamps for the last few hours.

Every state

Offline keeps the last synced dashboard and marks the acknowledgement local. Empty is a real lab with nothing scheduled, not a failed request.

Data contract

  1. Everything in. Instruments, alerts, samples, schedule, activity, and asOf are the whole input. Replace the MOCK_* exports with one adapter that returns the same five arrays.
  2. Acknowledgement out. onAcknowledge(alert) fires after the local state moves. Persist it, then let the next fetch return the acknowledged record; the alert stays visible either way.
  3. Sample open out. onSampleOpen(sample) is the handoff to your sample or data route. Instrument selection and the active sample are local and URL-addressable.

Install

The workbench installs its instruments and elements from the registry. No private runtime, no hidden provider.

Rules

  • Acknowledge, do not delete. An alert is a record even after someone has seen it.
  • Instrument state needs text. Color is an accent on the label, never the label itself.
  • An ETA is data. Show minutes when the run is moving, show a clock time when it is scheduled, and show why when it is blocked.
  • Offline is a mode, not an error. The last snapshot stays readable and local actions say they are local.
  • The count in the header, the cards, and the table must describe the same snapshot. Pass one `asOf` and use it everywhere.
