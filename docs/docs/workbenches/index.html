Workbenches

A workbench is a whole screen, not a widget demonstration. Copy one in and replace the mock adapter with your data; the layout, states, and keyboard behavior are already done.

What every workbench includes

  • Every data state: loading, empty, error, permission denied, and offline. None of them is a blank screen. The shell adds offline, command palette, inspector, and mobile navigation states.
  • A mock adapter with realistic, non-sensitive data. Replace it with your query; the components do not know where rows come from.
  • URL-addressable filters, sort, and selection, so a colleague can open the exact view you are looking at.
  • A mobile layout, a print layout, and keyboard paths for every action that matters.
  • Composition only. A workbench installs elements and instruments from the registry; it does not hide a private runtime.
