Run Comparison

"Which run was better?" is usually answered from memory. A text diff cannot help: it does not know that 6100 psi and 420 bar are the same kind of quantity in different clothes, or that a 0.02 mL/min change is noise while a 2 min gradient change is not.

Two AU5800 runs. Column temperature, injection volume, and wavelength match. Flow rate and gradient moved, so retention, resolution, and plate count moved with them. Carryover exists in one run only. Pressure is recorded in bar and psi, so no delta is computed — the row says unit mismatch instead of inventing a number.

What it checks

  • Never subtract across units. A bar-to-psi comparison is a unit mismatch, not a delta. The row is flagged and the export records the status.
  • Tolerance is explicit. A change counts when it exceeds the absolute tolerance for that key or the relative tolerance for the comparison. The default is 0.1%, shown in the toolbar so nobody has to guess.
  • Missing is its own status. A metric recorded in one run and absent from the other is not "no change". It is missing, counted, and visible in the diff.
  • Only differences, on request. The toggle hides unchanged keys while the summary keeps the total count, so a long parameter list stays reviewable.
  • More than two runs compare to the first. The table shows every run and computes the delta between the baseline and the latest. The footer names both.
  • The export is the diff, not the table. JSON carries the runs and the summary. CSV carries one row per key with values, delta, relative change, and status.

What it does not claim

A changed value is not a regression. The instrument reports differences against a tolerance; whether a 0.2 min shift in retention time matters is a method question. Set absoluteTolerance per key when the method defines one, and leave it unset when the difference is worth seeing.

Data contract

  1. Run. id, label, optional startedAt and instrument, plus parameters and metrics records.
  2. Value. A number with an optional unit and uncertainty, or a string, boolean, or null. A null value is present-but-empty; an absent key is missing.
  3. Options. relativeTolerance (default 0.001) and absoluteTolerance keyed by parameter or metric name.
  4. Helpers. compareValue, compareRuns, comparisonCsv, and comparisonJson are exported.
  5. Status vocabulary. Same, changed, missing, unit mismatch, and not comparable. The last covers values that are neither numeric nor equal, such as a string versus a number.

Accessibility

  • Each section is a table with a caption, row headers for keys, and end-aligned tabular numerals.
  • Status is a word with a border and a tone. The unit-mismatch banner repeats the count in a sentence.
  • The differences toggle is a pressed button, not a switch with hidden state.
  • The table collapses the delta column below 640 px and keeps the status visible; missing values stay as an em dash with a title.

Status

Ready. The comparison is deterministic and pure; use compareRuns in a job summary without rendering the table.
