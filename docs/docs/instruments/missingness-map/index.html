Missingness & Censoring Map

A heatmap of missing values treats every gap the same. This map does not: a sample that was never collected, an assay that was not applicable, a value below the detection limit, and a lost aliquot are four different facts with four different consequences.

export carries codes, not measurements

Twelve samples across nine assays. Haemolysis removes creatinine and urea together; IL-6 was never collected at this site; troponin is censored rather than missing. The right rail ranks the columns by completeness and names the pairs that fail together. Toggle Incomplete only to review the gaps, or export the coded matrix.

What it checks

  • Censored is a state, not a gap. A below-limit value is present in the data and absent from the numbers. It gets its own glyph, its own count, and its own code on export.
  • Structural gaps are separated. "Not applicable" and "not collected" are not missing-at-random. The map keeps them distinct from a lost measurement so an imputation model cannot silently treat them the same.
  • Codes are declared once. The source vocabulary — ND, HEM, QNS — maps to a kind and a label. A string that is not a declared code is a data value, not a missing value.
  • Columns report completeness. Each assay shows its percentage present, so the weakest column is visible before a model is fitted.
  • Co-missingness is ranked. The three most frequent column pairs missing in the same rows are listed. That is how a haemolysis pattern or a site-level omission shows up.
  • The export carries codes, not values. A completeness matrix can be shared with a reviewer or a statistician without disclosing a single measurement.

How cells are resolved

  • A number is present. A string that matches a declared code takes that code's kind; any other string is present.
  • null, undefined, and "" resolve to the declared missing code, or to a generic missing state when none is declared.
  • An object { kind, code?, note? } overrides inference. Use it when the same token means different things in different columns.
  • Censoring detection is opt-in: a value is censored when the cell says so or matches a censored code. The map does not infer a limit from a number.

Data contract

  1. Columns and rows. Columns need an id and a label. Rows need an id and a values record. A missing key is treated as missing, not as an error.
  2. Codes. Each code has code, label, and kind. Kind is one of missing, censored, notApplicable, or notCollected; present is inferred.
  3. Helpers. summarizeMissingness and missingnessCsv are exported, along with the default codes and glyph map, so a validator and the UI agree.
  4. Co-missingness counts missing and notCollected together. Censored values are excluded: they were measured, just not above the limit.

Accessibility

  • The matrix is a table with column headers, row headers, and a caption. Every cell has an accessible label naming the record, the column, the state, and any note.
  • State is carried by a glyph and a border style before it is carried by color. The legend repeats both.
  • The compact 1.25 rem cells are below the 24 px target size, so the table is a review surface rather than a touch control surface; there are no clickable cells to miss.
  • Vertical column labels are marked up as ordinary header text; only the visual rendering is rotated. Screen readers announce the label normally.
  • The map scrolls inside its own container at narrow widths; the page does not.

Status

Ready. It deliberately does not impute, test missingness mechanisms, or draw a correlation matrix. Those are analysis decisions; this instrument makes the pattern visible and the vocabulary explicit.
