Measurement Table

A data table is type-agnostic. A measurement table is not. Every column declares what it holds, what unit it is in, how precisely it was measured, which tokens mean missing, and what the detection limit was.

A synthetic serum panel. Glucose carries a method uncertainty, creatinine has two missing codes, troponin is censored below 0.01 ng/L, and one glucose value arrived as the string "pending". Switch to Needs review to see only the rows that carry a gap or a flag, or export the CSV and inspect the header and qualifier columns.

What it checks

  • A quantity without a unit is flagged. The rule is not a style preference. A number whose unit is only in the column title, the methods paragraph, or the reader's memory is not a measurement. The header says unit not set and the summary counts it.
  • Missing codes are declared, not guessed. ND, HEM, and QNS each carry a label and a kind. The cell shows the token, the legend explains it, and a screen reader hears the meaning.
  • Censored is not zero. A below-limit value renders as < 0.01 and exports as a qualified string. It never becomes a zero that later statistics will happily average.
  • Strings are not silently coerced. A non-numeric value in a numeric column is marked unparsed, tinted, and counted. The table does not turn "pending" into NaN and move on.
  • Uncertainty stays attached. Column-level and cell-level uncertainty render as ± beside the value and become their own CSV column. A measurement without its error is incomplete, not clean.
  • The footer reconciles the columns. Each column reports n and how many cells need review, so nobody has to count gaps by eye before writing the methods.

How values are read

A cell accepts a number, a string, null, or an object with value, uncertainty, censored, missing, note, and flag. The rules are deterministic and exported as pure helpers.

  • Column type. quantity and number are numeric; category, datetime, and text are not. A unit implies quantity when no type is given.
  • Precision. Set precision to fix the decimal places. Without it, values render up to four decimals and switch to exponential outside 10⁻³–10⁶. Display rounding never changes the export, which carries full precision.
  • Uncertainty. A column uncertainty can be absolute or relative; a cell uncertainty overrides it. Hide the whole thing with showUncertainty: false when the table is a lookup rather than a report.
  • Censoring. Give a cell { censored: { limit } } and it renders as a limit. A column detection limit supplies the default for cells that only declare censoring.
  • Flags. ok, warning, and fail add a glyph, a tint, a tooltip, and an accessible label. The glyph carries the meaning; the color is a second cue.

Data contract

  1. Input. columns and rows are required. A row has an id, an optional label, and a values record keyed by column id. Missing keys are empty cells.
  2. Columns. id, label, optional type, unit, precision, missingCodes, detectionLimit, uncertainty, and showUncertainty.
  3. Export. onExport(csv) fires before the download. The header appends [unit], uncertainty becomes a companion column, and flags become a trailing Flags column. Notes are display-only.
  4. Filtering. The row filter changes what is on screen, never what is exported. The whole table is the record.
  5. Pure helpers. normalizeMeasurementCell, summarizeMeasurementColumns, formatMeasurementCell, and measurementTableCsv are exported for validation and tests.

Accessibility

  • A real table with a caption, column headers, and row headers. Numeric columns are end-aligned and use tabular numerals.
  • Missing codes, censored limits, and flags each carry an aria-label or screen-reader text; the glyph is never the only carrier.
  • The row filter is a labelled button group with aria-pressed, not a custom dropdown.
  • At 320 px the table scrolls inside its own container while the page keeps its width. The page does not move sideways.
  • No entrance animation, no counting numbers. Reduced-motion users see the same table.

Status

Ready. The semantics, export, and keyboard path are complete and tested. It is a display instrument: it does not parse files, infer units, or edit values. Pair it with Quantity Input for entry and with Import Mapper (planned) for intake.
