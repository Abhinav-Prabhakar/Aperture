1-based, inclusive coordinates. Click a feature to highlight it. Search is exact and case-insensitive.

The demo is a synthetic 1,200 bp construct, not a real plasmid. Select a feature, search for a motif, or copy the normalized sequence. The CDS is selected on load so its translation and completeness check are visible.

What it checks

  • Coordinates are 1-based and inclusive. A feature from 121 to 426 is 306 bases. The viewer reports the length; it does not make you subtract in your head.
  • CDS completeness is explicit. A coding sequence must start with ATG, end with TAA, TAG, or TGA, and have a length divisible by three. Anything else is a warning with the reason, not a silent translation.
  • Strand is handled. A feature on the minus strand is reverse-complemented before translation. The sequence track still shows the bases as stored.
  • Search is exact and overlapping. Motif search is case-insensitive, ignores whitespace, and reports every start position. GCT in ATGGCTGCTTAA has two hits.
  • GC is a measurement, not a decoration. It is computed over A, C, G, and T only. Ambiguous bases are ignored, and a sequence with no canonical bases reports —.
  • Unsupported bases are shown. The record still renders, with a warning. Hiding a bad character is worse than showing it.

Data contract

  1. Record in. record is null or an object with id, name, sequence, an optional topology, source, and features. Null renders the empty state.
  2. Features are annotations. Each has a stable id, a kind, a name, start and end, and an optional strand and note. Kinds are CDS, promoter, RBS, terminator, origin, primer, restriction, regulatory, and other.
  3. Selection in and out. defaultFeatureId sets the first selection; onFeatureSelect(feature) reports changes. The viewer never fetches or mutates the record.
  4. Copy out. onCopy(sequence) fires with the normalized sequence — uppercase, no whitespace or line numbers, U converted to T.
  5. Pure helpers are exported. normalizeSequence, reverseComplement, translate, findMatches, gcContent, analyzeCds, and parseFasta. Use them on the server, in a script, or in your own validation.

Accessibility

  • Every feature is a labeled button with aria-pressed; the compact track is a second control with the same accessible name.
  • Search has a visible label association, and the match count is a live status region. An unmatched query says “No matches” instead of going blank.
  • The copy button changes its label to “Copied” and back, so the state is available without a toast.
  • Status is never color alone: the warning has text, and the feature legend uses labels alongside the tracks.
  • Layout uses logical properties and wraps bases at narrow widths, so RTL and 320 px screens do not create a horizontal scroll trap.

Preview status

The API and rendering are complete and tested. The life-sciences vocabulary and defaults are still awaiting a domain-advisor review, so this instrument is marked preview rather than ready. Treat it as usable, not final.
