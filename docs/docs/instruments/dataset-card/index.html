Dataset Card

A card that shows fields is a card. A dataset card knows which fields are required, says "not recorded" when one is absent, distinguishes raw from derived from published, and produces a citation from the same record it displays.

A raw serum export at version 1.2.0. The completeness strip counts eight required fields, the checksum and citation copy in one action, and the related records point at the run that produced the file and the analysis set derived from it. The warning keeps the disclosure attached to the data, not buried in a README.

What it checks

  • Completeness is counted, not implied. Eight required fields are checked: title, description, owner, license, method, checksum, access, and version. The strip names what is missing.
  • A missing checksum is a warning. Not a blank line. The bytes cannot be verified, and the card says so in the integrity column.
  • Stage is explicit. Raw, derived, and published datasets have different obligations and different citations. The badge makes the difference visible before the title.
  • Access conditions travel with the data. Open, restricted, embargoed, or closed, plus the note that says what a requester must do.
  • The citation is generated. Owner, year, title, version, repository, and DOI become a DataCite-style citation. Override it when the repository has its own format.
  • Relationships are directional. Derived from, supersedes, part of, documents. A dataset is rarely an island, and "derived from" is the link an auditor asks for.

What it refuses to do

  • It does not upload, fetch, or mint a DOI. The card is a record of the identifier, not a client for the repository.
  • It does not validate that the checksum matches the bytes; that requires the bytes. It records the algorithm and the value so a pipeline can.
  • It does not decide whether a license is appropriate. It refuses to let the license be absent without saying so.
  • It does not render a visibility switcher or an edit form. Pair it with Metadata Editor when the record is being authored.

Data contract

  1. Required. id, title, stage, version, and owner.
  2. Optional. Description, affiliation, contributors, license, DOI, repository, format, size, checksum, method, dates, access and access note, keywords, related records, a citation override, and a warning.
  3. Checksum. { algorithm, value }. The full hash is displayed and copied; the completeness strip shows only a prefix.
  4. Helpers. datasetChecklist, datasetCitation, and datasetMetadataJson are exported. The JSON contains the checks and the citation, so an archive can store one artifact.
  5. Custom requirements. Pass requiredFields to check a funder's or repository's set instead of the default eight.

Accessibility

  • Identity is a definition list, not a grid of divs; each label is associated with its value.
  • Completeness is announced as "6 of 8 required fields recorded" plus the missing names. The percentage is a supplement, not the message.
  • The checksum wraps at character boundaries instead of forcing a horizontal scroll, and the copy action reports success in text.
  • Badges carry words, not just tone: Raw, v1.2.0, DOI. Color is never the only signal.

Status

Ready. It is the identity layer the other instruments link to: the Measurement Table is a view of a dataset, the ledger explains how its analysis set was made, and the manifest records the runs that touched it.
