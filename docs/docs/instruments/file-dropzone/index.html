File Dropzone

Files are data. A dropzone should say what it accepts, reject the rest with a reason, and keep the queue visible while the upload runs.

The demo stops at queued; wire onFiles to your uploader and set each item’s status as it changes.

Rules

  • accept is a convenience, not security. Validate type, size, and content on the server as well.
  • Name the limit in human units and show the same unit in the error. Sizes here use decimal units: 1 MB = 1,000,000 bytes.
  • Reject per file, not per batch. One bad file should not discard the good ones.
  • Keep the file name visible and unchanged in the queue. A checksum is provenance; a renamed file is not.
  • A retry is the same file, not a new one. Remove the queue row only after the user can see what happened.
