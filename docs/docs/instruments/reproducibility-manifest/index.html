Reproducibility Manifest

"It ran on my machine" is not a record. A manifest is: the exact commit, the command, the environment, the package versions, the seeds, and a hash for every input and output. It is the difference between a result someone can repeat and a screenshot someone has to trust.

A clean run of a mixed-model script: commit, command, R version, six pinned packages, parameters, a seed, three hashed inputs, and two hashed outputs. The checks panel shows six of six. Copy the JSON, export it next to the results, or copy the reproduce command.

What it checks

  • A dirty tree is called out. Uncommitted changes mean the commit does not contain the code that ran. The manifest says so before the command.
  • Every input and output needs a hash. A path alone identifies a name, not bytes. Missing hashes are listed, and the reproduce command is withheld when the tree is dirty.
  • The environment is pinned. Language, version, platform, and package versions. A manifest with no package list is marked incomplete.
  • Seeds are part of the result. A stochastic analysis without a seed is not reproducible, even if the command is. Seeds render as their own block.
  • The command is shown, not summarized. The exact string, with a copy action and a git checkout … && … recipe when the tree is clean.
  • One artifact holds it all. The export is a JSON document with the record, the checks, the warnings, and the reproduce command.

What it cannot do

  • It does not compute hashes, inspect the repository, or read the environment. Your runner produces the facts; the manifest records and validates them.
  • It does not guarantee that a checkout will rebuild the environment. Pinning versions is necessary, not sufficient; containers and lockfiles still matter.
  • It does not prove the result is correct. It proves the result is traceable, which is a lower and more achievable bar.

Data contract

  1. Identity. id, project, createdAt, commit, optional branch, and dirty.
  2. Environment. Language, optional version and platform, and an optional package list of name and version.
  3. Execution. Optional command, params record, seeds record, and duration in seconds.
  4. Artifacts. Inputs are required (an empty array is allowed); outputs are optional. Each has a path, an optional hash, and optional bytes.
  5. Helpers. manifestChecklist, manifestWarnings, reproduceCommand, and manifestJson are exported.

Accessibility

  • The command is a pre block with a copy button; long lines scroll inside the block, not the page.
  • Check status is a glyph plus a screen-reader word ("recorded" or "missing"), with the detail in a title.
  • Hashes and paths use monospace and truncate with a title rather than wrapping mid-token.
  • Warnings are one sentence in the status strip and repeated item by item in the checks list.
